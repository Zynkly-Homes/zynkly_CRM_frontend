01_folder Structure for this component

Sidebar/
├── index.ts                   ← barrel export (import from here only)
├── Sidebar.tsx                ← thin shell, ~90 lines, layout only
├── types.ts                   ← all TypeScript interfaces in one place
├── constants.ts               ← no more magic numbers anywhere
├── hooks/
│   ├── useSidebar.ts          ← collapsed + mobile + accordion state
│   ├── useDarkMode.ts         ← dark mode isolated, reusable anywhere
│   ├── useAuth.ts             ← logout logic, completely separate
│   └── useNavigation.ts       ← nav items built from permissions + useMemo
└── components/
    ├── NavItem.tsx            ← NavLinkItem + NavButtonItem + NavIcon + NavChevron
    ├── NavList.tsx            ← proper component replacing renderNav function
    ├── SidebarLogo.tsx        ← logo + collapse button
    ├── SidebarToggle.tsx      ← floating pill with reusable IconButton inside
    ├── UserProfile.tsx        ← Avatar + ThemeToggle + ProfileDropdown sub-components
    └── MobilePanel.tsx        ← portal + backdrop + MobilePanelHeader


02_notes why we chose it?

Key industry practices applied:
Barrel export (index.ts) — consumers write import Sidebar from "@/components/Sidebar", never deep paths
Custom hooks own their state — Sidebar.tsx has zero useState for business logic (only profileDropdownOpen which is pure UI)
useMemo in useNavigation — nav array doesn't rebuild on every render
No magic numbers — every z-index, breakpoint, duration lives in constants.ts
NavList is a real component — not a function called inside JSX, so React can reconcile it properly
UserProfile broken into Avatar + ThemeToggle + ProfileDropdown — each independently testable
SidebarToggle has a reusable IconButton — no duplicated hover logic
